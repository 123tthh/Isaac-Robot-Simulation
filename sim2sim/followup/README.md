## What joint 7's zero limit means / 第七关节零限位读数

The earlier `[0, 0]` came from `GET /robot/R1/joints` for
`left_joint7_motor` and `right_joint7_motor` on `r1_fixed_omnisim.urdf`
([historical response](../results/simple_motion.json), `joint_mapping.joints`).
That endpoint reads `JointParameters.minStop/maxStop`. On the full-range joint,
they remain unset, while `Motor.getMinPosition()/getMaxPosition()` returns
[−6.283, +6.283]. The new release still reports `[0, 0]` through the same
snapshot helper for both R1 variants. Native `Motor.setPosition()` plus
`PositionSensor.getValue()` show small physical motion; endpoint orientations
change as well. The new importer also gives correct motor limits to ordinary
and asymmetric revolute joints.

历史 `[0,0]` 来自 harness 的机械 stops 字段，不代表电机失去行程。新版本原始 R1 的左右
joint 7 均能按 ±0.25 rad 小幅运动；这里未测试 R1 完整 ±6.283 rad 行程或带载抓取。

## Contact control / 接触对照

Each run starts at simulation t=0 and ends at 2.56 s. A 4 cm, 50 g cube starts
at z=0.8 m and falls under gravity 9.81 m/s². The static Box floor top stays
at z=0.025 m; the nominal resting cube centre is z≈0.045 m. There is no R1,
URDF or mesh in these worlds. On v9.0.0-rc.2:

| Condition / 条件 | Final centre z (m) | Final contacts | Outcome |
| --- | ---: | ---: | --- |
| 16 ms, 0.05 m floor, one substep | −31.546318 | 0 | Through floor |
| 8 ms, 0.05 m floor | 0.044892 | 4 | Supported at end |
| 16 ms, 0.05 m floor, four substeps | 0.044892 | 4 | Supported at end |

The 16 ms failing run briefly reports contacts before crossing. The older
baseline additionally tested 4 ms and a 0.20 m floor; both supported the cube
at the end. [Independent native MuJoCo 3.11.0 control](results/mujoco_3_11_0_control.json)
shows the same step/thickness trend. This suggests a discrete-step thin-floor
penetration issue, not a proven engine-internal cause. R1's ignored 1.05 mesh
collision scale warning remains; it cannot directly explain the robot-free
primitive case. Final support does not certify acceptable transient penetration.

16 ms 失败案例曾短暂出现接触。减小步长、增加子步可让方块在末端稳定，仍未证明求解器
内部根因，也未验证抓取任务。R1 的 1.05 碰撞缩放警告独立存在。

## Reproduce / 复跑

Fetch hydrated R1 meshes first (`git lfs install && git lfs pull`). Build the
pinned OmniSim source with its [Linux setup instructions](https://github.com/omnilink-tech/omnisim/blob/v9.0.0-rc.2/docs/developer/quickstart.md),
including the mandatory Newton runtime. `OMNISIM_HOME` points to that checkout.
From this repository root:

```bash
python3 sim2sim/followup/scripts/validate_published.py
python3 sim2sim/followup/scripts/make_worlds.py
export OMNISIM_HOME=/path/to/omnisim
python3 sim2sim/followup/scripts/run_probes.py \
  mid_empty r1_portable_joint7 range_probe thin_16ms thin_8ms thin_16ms_sub4
```

`run_probes.py` writes new measurements under ignored `outputs/omnisim_followup/replay`.
It accepts `--output-dir` for a separate run. Set `OMNISIM_PHYSICS_PYTHONPATH`
when the linked interpreter uses an isolated Newton installation, and
`OMNISIM_NATIVE_LIB_PATH` if local system libraries are overlaid. No recorded
absolute source path is required; world URDF references are relative to the
committed fixtures. To compare the old version, check out its pinned source and
expect the old import failures; its raw outcomes are already preserved.

The worlds are generated by [make_worlds.py](scripts/make_worlds.py); the native
[controller](controllers/local_probe/local_probe.py) reads motor bounds,
PositionSensors, endpoint orientations and contact points. No task completion,
camera accuracy, payload, hardware transfer or Isaac/OmniSim equivalence is
claimed. Detailed historical source and mesh audit: [evidence](results/historical_evidence_audit.json).

Published results are limited to experiment fixtures, raw measurements, solver
sidecars, relevant engine excerpts and their checks. Local build trees, full
host logs and private correspondence remain outside Git.
